# Opus 5.5 音乐 MV 制作调研（知乎教程 · 2026-10-26）

> origin: ai · 2026-10-26 · 来源: https://zhuanlan.zhihu.com/p/2097864768132595902 （作者 yjm002top）
> 主题: 如何用 Claude Opus 5.5 做一支音乐 MV —— 代码逐帧渲染完整教程

## 1. 核心方法

Opus 5.5 **不生成视频**，而是**写代码画每一帧**：
- 写一个网页（HTML/canvas），描述「第 N 秒时画面里有什么」
- 用无界面 Chrome（headless）从 0 秒到结尾每秒拍 24 张照
- ffmpeg 把照片和音乐拼成 MP4

**好处**：角色每个镜头一致不跑偏；改细节只改几行代码。

## 2. 工具链: painted-animation skill

- GitHub: `Joker-chichi/claude-mv-skill`（转载自爆火 MV 开源工程）
- 内置:
  - 水彩笔刷引擎（p5.js + p5.brush）+ 逐帧渲染脚本
  - 角色 Clawd: 31 种表情、5 个转身视角、帽子/表情符号配件
  - 节拍检测脚本 beat_grid.py + 逐字卡拉 OK 歌词模块
  - 动画指南（防 AI 味规则）

## 3. 七步流程

1. **准备材料**: 歌曲音频 mp3 + LRC 歌词 + 参考视频（定风格）
2. **装 skill**: 把 GitHub 链接发给 Claude
3. **选段测节拍**: 选 40-60s 高潮段；beat_grid.py 测 BPM（例: 80.1 BPM，一拍 0.749s，一句歌词≈4拍≈3s）
4. **写分镜**: 每句歌词一个镜头；一句歌词只能讲一件事
5. **搭角色场景道具**: 两个文件——世界/角色/道具（hj_set.js）+ 镜头（hj_shots.js）
6. **逐镜头制作 + contact sheet 审查**: 每 0.4-0.6s 截一帧拼大图，AI 自己看图找问题；前后渲十来轮
7. **渲染出片**: 草稿模式确认节奏 → 本地完整画质渲染

## 4. 渲染性能数据（59s 全片）

| 方式 | 画质 | 每帧耗时 | 全片耗时 |
|------|------|---------|---------|
| 云端完整画质 | 1080p/24fps/水彩纹理 | ~50s | ~20h |
| 云端草稿 | 半分辨率/12fps/平涂 | ~4s | ~50min |
| 本地有显卡完整画质 | 1080p/24fps/水彩 | ~1-3s | ~0.5-1h |

本地渲染命令:
```bash
node render.mjs --sheet=10.5,40.4 --cols=2 --w=960 --out=out/check/test.jpg  # 测试图
node render.mjs --frames --workers=4                                          # 全部帧（可中断续渲）
node render.mjs --encode --audio=assets/clip.m4a --out=out/MV.mp4             # 合成 MP4
```

## 5. 动画防 AI 味规则（动画指南要点）

- **画面里不写字**（除底部卡拉 OK 歌词）——情绪靠表情+头顶小符号（❤❗音符雨云）
- 每个镜头都有事件，每个接缝都有转场
- 角色不能太小、动作要有预备（anticipation）
- 重复歌词要「升级」不重拍（第二遍换角度讲同一件事）
- 首尾呼应（开场缺角月亮→结尾补全满月）

## 6. Contact Sheet 审查法（最有价值的方法论）

AI 写代码时「看不见」画面，必须渲染出来自己看：
- 每写完一批镜头 → 渲 contact sheet（6-24 帧/轮）→ 自己看图找问题
- 实际发现并修掉的问题类型:
  - 元素太小看不清（小人指甲盖大小）
  - 元素悬空（浇水壶没握在手里）
  - 元素越界（山坡超出画框）
  - 动作看不懂（钟挂太高够不到→加凳子+推近镜头）
  - 时间算错（入场时间不对、光圈收拢来不及）
  - 信息密度不足（观众没时间看懂）

## 7. 踩坑记录

- 音频和歌词必须配套（参考视频只定风格，卡点只认音频+LRC）
- 先做高潮段（40-60s），别整首歌
- 网络受限时 npm/Google Fonts 连不上 → 从 GitHub 下 p5，歌词用系统思源宋体
- 没显卡用草稿模式（--fast 平涂 + --half 半分辨率，快十几倍）
- 「缩到 0」的形状会让渲染器报错 → 尺寸太小时用纯色盖住
- 水彩笔刷非常吃显卡

## 9. 与 d1 项目的关系

- d1 现有技术栈（Node+canvas 帧序列→ffmpeg）与 Opus 5.5 方法**同构**，都是代码逐帧渲染
- 关键差异: Opus 5.5 用 p5.js 水彩笔刷（质感更丰富）+ contact sheet 自审查循环 + 动画指南防 AI 味
- **可借鉴**: ① contact sheet 自审查法（替代纯 check_overlap）② 动画指南规则 ③ 歌曲卡点（BPM 锁节拍）④ 角色表情系统（31 种表情+预备动作）
- arena agent mode 可行性: batch-11 E25-E28 已由 arena 产出并通过 41/41 check（实证锚点），arena 可以写渲染代码；水彩笔刷 p5.js 方案 arena 同样可用
